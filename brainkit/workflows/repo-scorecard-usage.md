# Repo Scorecard Usage

This workflow explains how to use repo scorecards to improve readiness across the ecosystem.

## Goal

Use scorecards to detect missing structure, missing docs, missing tests, and weak integration clarity before problems spread.

## Suggested Use

1. collect present files for the target repo
2. confirm lane is known
3. check whether tests exist
4. check whether integration docs exist
5. run the scorecard script
6. create an improvement mission from the missing items

## Best Practices

- score active repos regularly
- prioritize low-scoring repos in high-risk lanes first
- use scorecards as improvement signals, not blame tools
- turn repeated scorecard gaps into template upgrades
