# Canva Master Template Duplication Playbook

Purpose: create the first `lippytm.ai Control Hub` Canva card, then duplicate it as the master template for `Chatlippytm.ai.Bots`, `AllBots.com`, and every future lippytm repository portfolio card.

## Big goal

Build one strong Canva card first, then duplicate it instead of starting over every time.

The system:

```text
Card 1: lippytm.ai Control Hub
  -> Duplicate as AI Bot template
  -> Duplicate as AllBots management template
  -> Duplicate as Web3AI template
  -> Duplicate as Education template
  -> Duplicate as Creative/Mythos template
  -> Duplicate as Funding/GetBizFunds template
```

## Quality rules before duplicating

Do not duplicate the master until the first card passes this checklist:

- [ ] Headline readable on a phone.
- [ ] CTA visible.
- [ ] Nodes are not overcrowded.
- [ ] The card explains the project in 3 seconds.
- [ ] The design looks professional enough for LinkedIn.
- [ ] The design has enough energy for Instagram/Facebook.
- [ ] No guaranteed funding/income claims.
- [ ] Brand footer is visible.

## Design flexibility for all repositories

### If a repo is professional/business

Use:

- Dashboard visuals.
- Clean typography.
- Practical CTA.
- LinkedIn-friendly tone.

### If a repo is bots/automation

Use:

- Conversation bubbles.
- Flow diagrams.
- Human handoff.
- Bot role cards.

### If a repo is education

Use:

- Learning paths.
- Course modules.
- AI tutor/robot teacher.
- Skill-building visuals.

### If a repo is creative/mythos

Use:

- More artistic visuals.
- Futuristic characters.
- Merch-ready design.
- Clear separation from business/funding pages.

### If a repo is Web3/product

Use:

- Website mockups.
- Wallet/payment nodes.
- Marketplace cards.
- Product roadmap visuals.

## Best practices for all repo cards

- One project, one purpose, one CTA.
- Use plain English first, creative language second.
- Make the card useful even without a caption.
- Avoid too many node labels.
- Save prompts in GitHub before designing.
- Export every card in at least square and website banner formats.
- Track which card gets clicks, comments, replies, or leads.
- Update the GitHub issue when a card is created.
