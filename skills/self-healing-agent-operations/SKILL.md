# Self-Healing Agent Operations

## Purpose

Help LippytmAI systems recover from errors, drift, broken pages, stale workflows, weak documentation, or disconnected business logic.

## Healing workflow

1. Identify the failure or drift:
   - build error
   - broken route
   - stale workflow
   - missing GitHub mirror
   - unclear skill
   - unsafe claim
   - broken link
   - automation gap
   - missing logging
2. Inspect the most relevant source of truth:
   - Zo Space route tools for live pages
   - `AGENTS.md` for routing memory
   - `Records/Workflows/` for operating systems
   - `Records/Plans/` for business direction
   - GitHub repos for source documents
   - `Skills/*/SKILL.md` for reusable procedures
3. Repair the smallest safe thing first.
4. Test or verify the repair.
5. Log what changed.
6. Add a prevention rule, checklist, skill update, or scorecard if the issue may repeat.

## Guardrails

- Do not delete important content without approval.
- Use route history, Git history, and backups when available.
- Keep public financial/funding content educational and cautious.
- Keep external automation changes approval-gated.
- Prefer reversible updates.

## Output format

For a self-healing task, return:

- Issue found
- Root cause
- Repair applied
- Verification result
- Prevention update
- Remaining risk
- Next safe action
