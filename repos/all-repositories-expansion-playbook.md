# All Repositories Expansion Playbook

Purpose: create one repeatable system for expanding every lippytm repository into a business asset with roadmap, Canva card, website section, CRM path, social pack, quality checklist, monetization idea, and GitHub tracking.

## Master principle

Every repository should answer seven questions:

1. What is it?
2. Who is it for?
3. What problem does it help solve?
4. What next action should people take?
5. What website section or page does it connect to?
6. What CRM tag should track interest?
7. What monetization or value path can it support?

## Repository asset formula

For each repo, create:

```text
README clarity
+ ROADMAP.md
+ OFFER.md
+ CANVA_PROMPTS.md
+ WEBSITE_COPY.md
+ SOCIAL_PACK.md
+ CRM_PATH.md
+ PERFORMANCE_LOG.md
+ QUALITY.md
= Business Asset
```

## Standard files to add over time

### README.md

Purpose:

- Explain the repo in plain English.
- Link to roadmap, offer, website, and related repos.

Must include:

- One-sentence explanation.
- Audience.
- Problem solved.
- Project status.
- CTA.

### ROADMAP.md

Purpose:

- Explain where the project is going.
- Convert a scattered idea into phases.

Must include:

- Phase 1: Organize.
- Phase 2: Design.
- Phase 3: Publish.
- Phase 4: Automate.
- Phase 5: Track.
- Phase 6: Monetize.
- Phase 7: Expand.

### OFFER.md

Purpose:

- Define the business offer connected to the repo.

Must include:

- Free offer.
- Paid offer.
- Service path.
- Affiliate path if relevant.
- CTA.
- Compliance notes.

### CANVA_PROMPTS.md

Purpose:

- Turn the repo into a visual asset set.

Must include:

- Portfolio card prompt.
- Website banner prompt.
- Instagram carousel prompt.
- LinkedIn graphic prompt.
- Pitch deck slide prompt.
- QR flyer prompt if relevant.

### WEBSITE_COPY.md

Purpose:

- Make the repo ready for lippytmai.getbizfunds.com or lippytm.ai.

Must include:

- Website section headline.
- Short copy.
- Bullets.
- CTA.
- CRM tag.
- Related offer.

### SOCIAL_PACK.md

Purpose:

- Make the repo publishable on Facebook, Instagram, and LinkedIn.

Must include:

- Facebook post.
- Instagram carousel slides.
- Instagram caption.
- LinkedIn post.
- Hashtag ideas.
- CTA.

### CRM_PATH.md

Purpose:

- Define what happens when someone clicks or asks about the repo.

Must include:

- Lead source label.
- CRM tag.
- Pipeline stage.
- Intake questions.
- Follow-up message.
- Related offer.

### PERFORMANCE_LOG.md

Purpose:

- Track if the repo is producing attention, clicks, leads, or opportunities.

Must include:

- Date.
- Asset/channel.
- Views.
- Clicks.
- Replies.
- Leads.
- Consult requests.
- Sales/commissions if any.
- Notes.

### QUALITY.md

Purpose:

- Keep the repo useful, clear, safe, and professional.

Must include:

- Clarity check.
- Link check.
- CTA check.
- Compliance check.
- Mobile-readability check for related Canva/website assets.
- No fake claims/testimonials.

## Quality best practices

- Plain English before technical detail.
- One project, one primary CTA.
- Every link should work.
- Every public claim should be safe and supportable.
- No guaranteed funding, income, approval, tax, legal, or investment outcomes.
- Affiliate links should be disclosed.
- Creative mythos should be separated from professional funding/consulting pages when necessary.
- Keep public pages mobile-readable.
- Keep GitHub as source of truth.

## Monetization best practices

Every repo should connect to at least one value path:

- Lead magnet.
- Service offer.
- Affiliate tool.
- Digital product.
- Consulting package.
- Bot workflow.
- Website section.
- Pitch deck asset.
- Course/education product.
- Merch or creative IP.
